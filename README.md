# Multi-Exit Relay

Интерактивный установщик для **российского Relay**: чистый TCP-проброс (DNAT, FORWARD, MASQUERADE) на любое число Exit-серверов с 3X-UI/Xray (VLESS + REALITY + TCP).

Relay только пересылает TCP. Он не ставит Xray, 3X-UI, HAProxy и Docker, не меняет SNI и не ходит на Exit, кроме проверки открытого TCP-порта. UDP не пробрасывается.

## Архитектура

```
Клиент
  │  TCP на внешний порт Relay
  ▼
┌──────────────────────────────────────────────┐
│ Relay (Ubuntu 22.04 или 24.04, публичный IPv4)│
│  DNAT + FORWARD + отдельный MASQUERADE       │
│  Xray / 3X-UI здесь не устанавливаются       │
└──────────────────────────────────────────────┘
  │  TCP 443 или TCP 8443, SNI не меняется
  ▼
┌──────────────────────────────────────────────┐
│ Exit (3X-UI / Xray, VLESS + REALITY + TCP)   │
│  слушает 443 и 8443                          │
└──────────────────────────────────────────────┘
  │
  ▼
Интернет
```

На каждый Exit N установщик создаёт две DNAT-записи:

- внешний порт Relay «для 443» → `IP_EXIT:443`
- внешний порт Relay «для 8443» → `IP_EXIT:8443`

Обратный трафик и новые соединения разрешаются отдельными правилами FORWARD. Для каждого Exit и каждого порта назначения ставится свой MASQUERADE. Одной общей MASQUERADE на весь сервер нет.

Правила живут в собственных цепочках `MEX_PREROUTING` (nat), `MEX_POSTROUTING` (nat) и `MEX_FORWARD` (filter). Переход из системных цепочек добавляется один раз. Каждое правило помечено комментарием `mex:<id>`. Чужие правила, политика INPUT/FORWARD, правила SSH и UFW не изменяются и не отключаются.

## Требования

- Ubuntu 22.04 или 24.04
- публичный IPv4
- root
- `iptables` с backend iptables-nft (обычный вариант Ubuntu)
- `netfilter-persistent` (пакет `iptables-persistent`; установщик предлагает поставить его отдельно)
- Bash 5+, `jq`, `iproute2`, `curl`

Exit уже должен слушать TCP 443 и TCP 8443. Этот репозиторий Exit не настраивает.

## Установка

**Не запускайте скачанный из интернета скрипт, не просмотрев его.** Команда ниже сразу скачивает и выполняет `install.sh`.

Безопаснее клонировать репозиторий, прочитать скрипт и только потом запускать:

```bash
git clone https://github.com/vpnmda/multi-exit-relay.git
cd multi-exit-relay
less install.sh
sudo bash install.sh
```

Однострочник, если код уже просмотрен и на сервере нужна именно эта версия из ветки `main`:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/vpnmda/multi-exit-relay/main/install.sh)
```

Если рядом со скриптом нет каталога `lib/`, установщик сам клонирует репозиторий в `/opt/multi-exit-relay` и перезапускает себя оттуда. Из обычного git-клона он работает без скачивания.

Меню:

1. Установить новый Relay
2. Добавить Exit
3. Удалить Exit
4. Показать конфигурацию
5. Проверить соединения
6. Проверить NAT и файрвол
7. Сохранить конфигурацию
8. Восстановить конфигурацию
9. Удалить установку
10. Выход
11. Изменить IP Exit (порты сохраняются)

Перед любым изменением файрвола создаётся резервная копия. Правила применяются только после подтверждения.

Команды ставятся как `/usr/local/bin/multi-exit-relay` и, если файл `/usr/local/bin/relay` свободен или уже указывает на этот установщик, как `/usr/local/bin/relay`. Чужой бинарник `relay` не перезаписывается.

## Один Exit

В меню выберите «Добавить Exit» или выполните:

```bash
sudo relay add --name Германия --ip 203.0.113.10
```

Установщик спросит название («Название сервера») и IP. Порты можно оставить автоматическими или задать два внешних порта Relay:

```bash
sudo relay add --name Германия --ip 203.0.113.10 --relay-port-443 443 --relay-port-8443 8443
```

Перед записью правил проверяется:

- что адрес — обычный IPv4, не дубль и не адрес самого Relay;
- что до адреса есть маршрут;
- что оба внешних порта свободны (локальные слушатели `ss`, уже настроенные Exit и чужие DNAT);
- что с Relay открываются TCP `Exit:443` и TCP `Exit:8443`.

Последняя проверка — **только доступность TCP-порта**. Это не проверка REALITY, VLESS или VPN. Если порт закрыт, Exit не добавляется. Явно принять это можно флагом `--force` или ответом в меню. Такое добавление помечается как принудительное.

## Несколько Exit

В установке нового Relay после каждого сервера задаётся вопрос «Добавить ещё один Exit? [Y/n]». Сначала показывается таблица, и только потом правила применяются.

```text
СТРАНА | IP EXIT | ПОРТ RELAY 1 | ПОРТ RELAY 2 | СТАТУС
```

Повторный запуск не меняет порты уже записанных Exit и не дублирует правила.

## Порты

Порты на стороне Exit всегда 443 и 8443. Внешние порты Relay по умолчанию:

| Exit | Порт Relay → 443 | Порт Relay → 8443 |
| --- | --- | --- |
| 1 | 443 | 8443 |
| 2 | 10443 | 18443 |
| 3 | 20443 | 28443 |
| 4 | 30443 | 38443 |
| 5 | 40443 | 48443 |
| 6 | 50443 | 58443 |

Формула слота N: `443 + (N-1)*10000` и `8443 + (N-1)*10000`, пока оба номера не больше 65535.

Если хотя бы один порт слота занят, берётся следующий свободный слот. После шестого слота ищется другая пара вида `P` и `P+8000` в диапазоне 1–65535. Порт 22 автоматически не назначается. Занятый порт не перезаписывается. Добавление нового Exit не сдвигает порты старых.

Ручные порты принимаются, только если оба свободны, различны и не равны 22.

## Ссылка для клиента

Ссылку VLESS возьмите в панели 3X-UI на **Exit**. В ней замените только адрес и порт:

- адрес — публичный IP Relay;
- порт — внешний порт Relay, который смотрит на нужный порт Exit (443 или 8443).

SNI, `pbk`, `sid` и `flow` оставьте как в исходной ссылке. Relay их не меняет.

Пример замены: ссылка на `203.0.113.10:443` для Exit, который на Relay выведен на порт 10443, становится ссылкой на `IP_RELAY:10443`.

## Проверка

```bash
sudo relay list
sudo relay status
sudo relay check
```

`relay check` печатает таблицу: TCP/443 и TCP/8443 до каждого Exit, наличие DNAT, FORWARD и MASQUERADE, `ip_forward`, состояние netfilter-persistent и конфликты портов. Колонки TCP снова означают только открытый TCP-порт, не рабочий VPN.

Меню «Проверить соединения» и «Проверить NAT и файрвол» показывают те же данные по частям.

После установки включены:

- `net.ipv4.ip_forward=1` через `/etc/sysctl.d/99-multi-exit-relay.conf`;
- сохранение правил `netfilter-persistent`, если пакет установлен;
- служба `multi-exit-relay.service`: при загрузке она ещё раз, без вопросов, собирает правила из `/etc/multi-exit-relay/config.json`.

Конфигурация лежит в `/etc/multi-exit-relay/`: `config.json`, `state.json`, `backups/`, `logs/`. В ней нет секретов. Запись атомарная: временный файл и `mv`.

## Удаление одного Exit

```bash
sudo relay remove --id exit-2
```

Будет предупреждение и подтверждение. Удаляются только правила с комментарием этого Exit. Остальные Exit продолжают работать. Чужие правила не трогаются.

## Полное удаление

```bash
sudo bash uninstall.sh
# или
sudo relay uninstall
```

Удаляются собственные цепочки и переходы, правило TCPMSS с комментарием `mex:tcpmss`, файл sysctl, если в нём нет посторонних настроек, служба и ссылки команд. `net.ipv4.ip_forward` в 0 не сбрасывается. `config.json` удаляется только после отдельного подтверждения или с `--purge-config`. Резервные копии остаются. Чужой NAT и файрвол не очищаются.

Файлы программы в `/opt/multi-exit-relay` эта команда не удаляет.

## Резервная копия

Копия создаётся перед каждым изменением и по пункту меню «Сохранить конфигурацию»:

```bash
sudo relay backup
```

Каталог `/etc/multi-exit-relay/backups/<время>-<причина>/` содержит `iptables.v4`, `ip6tables.v6`, снимок sysctl, `config.json` и `state.json`. Снимок iptables нужен для просмотра. Установщик не заливает его обратно в ядро.

## Восстановление

```bash
sudo relay restore --backup /etc/multi-exit-relay/backups/КАТАЛОГ
```

Берётся только сохранённый `config.json`. Собственные цепочки собираются заново. Весь файрвол из файла `iptables.v4` не восстанавливается, чужие правила не затираются и не возвращаются «как были» этой командой.

## Устранение неполадок

**Telegram открывается, а сайты нет.** Relay пересылает TCP на Exit и не выбирает, куда Exit ходит дальше. Смотрите маршрутизацию и outbound в Xray на Exit, а не правила Relay.

**UFW включён.** Его не нужно выключать. Разрешение стоит отдельной цепочкой `MEX_FORWARD` в начале FORWARD и срабатывает только для трафика настроенных Exit. Остальной трафик идёт в прежние правила UFW.

**Крупные сайты обрываются, мелкие открываются.** Проверьте, что в mangle/FORWARD есть одно правило `TCPMSS --clamp-mss-to-pmtu` с комментарием `mex:tcpmss`. На ядре без цели TCPMSS установщик пишет предупреждение и всё равно включает проброс: MSS тогда не зажимается. На обычном ядре Ubuntu 22.04/24.04 цель доступна.

**Провайдер режет порт или транзитный 443.** Попробуйте второй внешний порт того же Exit. Установщик не обходит блокировки провайдера.

**TCP-проверка не проходит.** С Relay должен открываться TCP до `Exit:443` и `Exit:8443`. Файрвол Exit должен пускать адрес Relay. Это не проверка ключей REALITY.

**После перезагрузки правил нет.** Должны быть включены `netfilter-persistent` и `multi-exit-relay.service`. Повторно применить конфигурацию: `sudo relay apply`.

**Порт занят.** Установщик не займёт порт, который уже слушает процесс, уже использует другой Exit или чужой DNAT. Выберите другую пару или освободите порт.

## Команды `relay`

```text
relay status
relay list
relay check
relay backup
relay restore --backup КАТАЛОГ
relay add --name ИМЯ --ip IP [--relay-port-443 N --relay-port-8443 M] [--force]
relay remove --id exit-N --yes
relay change-ip --id exit-N --ip IP [--force] --yes
relay apply
relay uninstall [--yes] [--purge-config]
relay help
```

`relay apply` нужен службе и ручному повторному применению. Он не спрашивает подтверждения и не ставит пакеты.

Для разработчиков: `MEX_DRY_RUN=1` печатает команды iptables и гоняет их через встроенный симулятор, не трогая ядро. `MEX_IPTABLES` подменяет двоичный файл iptables.

## Что проверялось

В репозитории есть автоматические проверки: `bash -n`, shellcheck, модульные тесты разбора адресов и портов, сборка правил в режиме dry-run и сквозной тест в сетевых пространствах имён (клиент → relay → два слушателя на 443/8443) с реальным iptables-nft, где это позволяет ядро.

На ядре без модуля TCPMSS реальное правило `--clamp-mss-to-pmtu` не устанавливается; установщик сообщает об этом, а симулятор проверяет, что команда формируется один раз. Прогон на боевых Relay-серверах этим репозиторием не заявляется.

Запуск всех проверок:

```bash
bash tests/run-all.sh
```
